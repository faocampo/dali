# Dali canvas critique

Target: `src/App.tsx` and the canvas shell, tool rail, and export dialog. Mode: Operate.

## Design specificity and overall impression

Dali's spacious canvas, compact header, and contextual editing controls suit product and engineering work. The strongest opportunity is to organize creation, navigation, and board operations into predictable locations. Preserve the familiar editor structure while improving those interactions.

This assessment covers the implemented editor. Planned collaboration, authentication, templates, and Gantt are outside this review. The score is a heuristic judgment based on source review and a bounded desktop inspection, not a complete accessibility or functional certification.

## What works

- The canvas dominates the interface, with direct board naming and a separate All boards action.
- Saved locally describes the current persistence model clearly; recovery paths exist in source.
- PNG scope explanations and output dimensions help users predict their export.

## Priority issues

1. **P1 — Export loses its keyboard boundary.** Tab from the last Share link action moved focus into the underlying canvas while the modal remained open. Escape and return focus worked. Contain forward/backward Tab navigation and make the background inert. Source: `src/header/ExportDialog.tsx:242` and `:264`. Suggested command: `$impeccable harden`.
2. **P2 — Tool and board operations compete in one scrolling rail.** At 1280 × 720, export/import were below the initially visible area. Eleven adjacent creation/layer choices have weak category boundaries. Keep creation tools stable, distinguish viewport/history actions, and give board operations a fixed named location. Preserve fast access for experienced users. Sources: `src/canvas/BlockSuiteCanvas.tsx:200`, `:230`; `src/canvas/EdgelessToolbarDragHandle.tsx:17`. Suggested commands: `$impeccable distill`, `$impeccable onboard`.
3. **P2 — PNG settings push Download below the fold.** Selecting PNG expands the dialog and displaces its completion action. Keep dimensions and Download in a stable footer; let settings scroll and compact the radio rows. Sources: `src/header/ExportDialog.tsx:101`; `src/index.css:863`, `:916`. Suggested command: `$impeccable layout`.
4. **P2 — Export's Share section points to upstream source.** Share link uses an upstream GitHub revision URL. The post-download promotional action uses the same URL. Move source attribution to a clearly labeled About location and keep export completion about the artifact. No sharing action was activated. Sources: `src/header/ExportDialog.tsx:52`, `:175`, `:209`; `src/header/links.ts:2`. Suggested command: `$impeccable clarify`.
5. **P2 — Viewport controls have incomplete accessible naming.** The browser accessibility snapshot exposed four unnamed buttons around the named zoom percentage. Establish each button's function and give it an explicit accessible name, then validate keyboard navigation. Exact upstream component mapping remains unverified. Suggested command: `$impeccable audit`.

## Cognitive load and user journey

Moderate load: chunking, grouping, and minimal-choice criteria need attention in the rail. An expert editor can reasonably expose many tools; category boundaries and stable locations matter more than an arbitrary tool-count limit. Arrival is calm and saved-state feedback reassuring. Discovery becomes less certain in the glyph rail, and PNG export introduces friction when Download moves out of view.

## Persona concerns

- Power user: repeated scrolling to find board operations and complete PNG export.
- Keyboard-dependent user: focus escapes the export dialog; unnamed viewport controls require investigation.
- First-time user: icon meanings and efficient editing shortcuts lack a discoverable overview.
