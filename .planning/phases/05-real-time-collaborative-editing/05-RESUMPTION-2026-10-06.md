## Sequential typography diagnosis and fix

The new production-browser regression holds a successful save or reservation-release response while the participant explicitly chooses the next format. Before the fix, size 48 applied but Bold generated no subsequent reservation: the helper rejected the new command while `pendingAction` still covered the preceding command's save/release lifetime. The deterministic release scenario failed at that missing reservation.

Explicit commands now run in arrival order. Every command checks the current runtime, discovers its required native scope, acquires a fresh server reservation and revalidates the operation before mutation. A rejected command completes once; it is not retried after somebody else's reservation ends. Pointer gesture denial behavior is unchanged.

`tests/collaboration-formatting-race.spec.ts` tests three real authenticated scenarios:

1. Hold the preceding save acknowledgment, choose Bold, then confirm size 48/weight 700 on both editors and after reload.
2. Hold the preceding release acknowledgment and verify the same result with a fresh reservation.
3. Have another authenticated editor acquire the object before releasing the held response. The explicit Bold receives 409 and leaves weight 400. Release the competitor and apply a new size change as an ordering barrier; the rejected Bold must remain absent, including after convergence and reload.

The first post-fix focused run passed all three. Subsequent combined runs also passed all three. The remote GitHub issue has not been changed.

## Presence diagnosis and fix

The canvas shell can move when native focus scrolls its container without a ResizeObserver callback. BlockSuite's cached bounding rectangle and the host rectangle can disagree with the actual shell origin. The overlay now projects from the live shell rectangle. Pointer-coordinate refresh is registered before reservation and presence capture listeners, so their model coordinates use the current origin. Incoming selection scaling is retained.

The inherited oracle also used a cached origin; it now compares the transmitted model point to the actual shell and cursor in one DOM operation at baseline, 50% canvas zoom and after the native Hand gesture. The focused tracer passed. This does not establish native browser-chrome 200% zoom acceptance.

The broad gate exposed a second test problem: presence replaces overlay children during refresh, so a separately resolved `boundingBox()` may return null. The tracer and multi-tab cursor checks now measure the matching element atomically. Their exact coordinate, movement and account-count assertions remain; no failing assertion was removed or widened.

The next integrated run passed both coordinate cases and exposed a distinct product defect in error recovery. A healthy incoming roster poll cleared an error from a failed outgoing presence publication. The live source now tracks failed publication independently: roster reads preserve the error, and an acknowledged publication recovers it. A new unit test fails on the old behavior and passes after the fix. The native browser case waits for a healthy poll while publication is failing, verifies that Retry presence remains available, then activates the retry by keyboard and observes recovery. Keyboard activation avoids a pointer-leave publication incidentally recovering before the explicit retry.

## Cross-browser pointer admission

After the 83-case Chromium gate passed, the prepared Firefox engine exposed another reservation-release race before the typography operation: the second input of a native double click could arrive while the first click's reservation was releasing. That input was discarded. A new explicit pointer gesture now waits for that release, revalidates native dependencies and acquires a fresh reservation. Replayed pointer events retain their original input timestamps so server latency cannot break the native multi-click interval. Escape still cancels the pending gesture before any late acquisition can replay it. The original Firefox case failed before this repair and passed afterward.

`tests/collaboration-pointer-race.spec.ts` adds held-release cases for native multi-click timing and cancellation. Its 600ms barrier deliberately exceeds the pinned native controller's 500ms interval; it is a timing assertion, not an arbitrary readiness wait.

Firefox's competing-owner typography case then reached the correct denial, convergence, save and reopen outcome, but the test expected Chromium's extra HTTP 409 console diagnostic. That expectation now follows the observed engine behavior; the real 409 response and all no-replay assertions remain mandatory. Unexpected browser errors remain failures.

The next Firefox run passed formatting, both pointer barriers, projection and tabs, then retained an editor in the roster after hard navigation. Aborting the held poll alone did not reliably retire the server connection. The live source now sends a best-effort keepalive disconnect for its original connection/account/epoch on disposal and pagehide, without reusing its aborted signal or applying a cleanup response to a newer runtime. Server authorization and broker expiry remain authoritative. Authorization/epoch failures mark the live source interrupted before teardown. A new unit test reproduced the missing disconnect; an existing poll-abort mock was updated to distinguish cleanup from polling while preserving its abort assertion. The focused Firefox navigation/layout scenario passes after the repair.
